# onepack

Skill packs **per repo**, never global. Part of OneStack. A repo turns on the packs it needs; everywhere else they cost nothing and are not in the `/` menu. Claude Code, VS Code and Orca read the same result.

| Pack | Group | How it is turned on |
|---|---|---|
| `pocock` | method | Plugin `pocock@onepack` (Matt Pocock's skills) → `/pocock:<skill>` |
| `pstack` | method | Plugin `pstack@onepack` (Lauren Tan's pstack, Claude Code build) → `/pstack:<skill>` |
| `speckit` | sdd | `specify init` writes `.specify/` and `/speckit-*` into the repo |
| `openspec` | sdd | `openspec init` writes `openspec/` and `/opsx:*` into the repo |
| `rea` | — | MCP server registered at Claude Code **local** scope for this folder only (`~/.claude.json`, never committed); installs Electron globally if missing |

**One pack per group per repo** (`--force` overrides; packs without a group, like `rea`, combine freely): two method packs compete with overlapping model-invoked skills; two SDD frameworks do the same job.

## Use

```bash
onepack list              # catalog, and what is on in this repo
onepack add pocock        # turn on (writes .claude/settings.json — commit it)
onepack remove pocock
onepack update            # onepack, marketplace, plugins, specify/openspec CLIs, this repo's Spec Kit/OpenSpec files
onepack suggest "migrar el login a OAuth en este repo"   # which pack fits, and how
```

**Which pack?** In Claude Code type `/onepack <what you want to do>`: it reads `CATALOG.md`, looks at the repo (stack, existing code, packs already on) and answers with the recommended pack(s) — or none —, why, the exact workflow commands, the cost, and the `onepack add` line; it runs it if you say yes. `onepack suggest` does the same from the terminal (one-shot, Sonnet by default; `ONEPACK_MODEL=haiku` is cheaper but more generic).

`CATALOG.md` is generated by the build from `guides/*.md` (hand-written: when to use, when not, workflow, cost) and the real skill list of each plugin, so it follows upstream.

Outside a git repo, onepack works on the current folder. Plugin packs use `--scope project`: the choice is committed in `.claude/settings.json`, so Orca worktrees and other clones inherit it.

## Always up to date

1. **Upstream → onepack:** `.github/workflows/build.yml` rebuilds `plugins/<id>/` every day at 04:00 UTC (and on any change to `packs.json`, `overlays/` or the build script) from the latest upstream commit, then commits.
2. **onepack → Claude Code:** plugins carry no pinned version, so every rebuild is a new version; the marketplace has `autoUpdate: true`, so Claude Code updates them after a session starts.
3. **CLI packs:** `onepack update` runs `specify self upgrade`, `npm update -g @fission-ai/openspec`, and refreshes the files of the current repo.
4. **onepack itself:** the CLI pulls `~/.onepack` at most once a day.

## Change a pack (overlays)

Your changes live in `overlays/<pack>/` and are re-applied on top of every upstream refresh:

- **Modify an upstream file:** edit it under `plugins/<pack>/…`, then save the diff as a patch and restore the file:
  ```bash
  git diff plugins/pocock/skills/engineering/tdd/SKILL.md > overlays/pocock/patches/010-tdd-spanish.patch
  git checkout plugins/pocock
  git add overlays && git commit -m "overlay: pocock tdd in Spanish" && git push
  ```
  The push triggers a build that applies it. Patches apply in file-name order.
- **Add a new file** (e.g. your own skill inside the pack): put it under `overlays/<pack>/files/<same path>`.
- **If upstream changes the lines your patch touches**, the build fails, opens an issue, and the last good build stays live. Fix or drop the patch.

Never edit `plugins/` by hand and commit it: the next build overwrites it.

## Add a pack

Add an entry to `packs.json` and a guide in `guides/<pack>.md`:
- **Plugin:** `upstream.repo`, `ref`, `path` (folder holding `.claude-plugin/plugin.json`), `include` (entries to copy, or `null` for all).
- **CLI:** `marker` (file or folder that shows it is on) and `files`; then add its `add` step in `bin/onepack`.
- **Any pack:** optional `npm_global` (npm packages the pack needs): `add` installs the missing ones globally, `update` keeps installed ones at `@latest`, `remove` leaves them (other folders may use them).

## Install

### Local (Mac)

Installed by **OneStack** (`onestack/sync-install.sh`): it copies the `/onepack` skill (`skills/onepack/`) with the other skills and runs this repo's `install.sh`, which clones to `~/.onepack`, links `~/.local/bin/onepack` and adds the marketplace with auto-update.

Standalone (CLI and marketplace only, no skill): `gh repo clone SoyDonOnega/onepack /tmp/onepack && bash /tmp/onepack/install.sh`.

### Cloud (Claude Code cloud sessions)

Cloud sessions run on a fresh VM that does not see `~/.claude/` on the Mac and does not install marketplace plugins. A cloud environment's setup script installs everything instead. Once, in claude.ai/code → the environment → **Setup script**, paste:

```bash
curl -fsSL https://raw.githubusercontent.com/SoyDonOnega/onepack/main/cloud/setup.sh | bash
```

Network access: **Limited** with **Allow package managers** on and `github.com` in the allowed domains. [`cloud/setup.sh`](cloud/setup.sh) installs into the VM:

- the own skills in [`cloud/skills.txt`](cloud/skills.txt) (public repos) and `/onepack` → `~/.claude/skills/`;
- `~/.onepack` (catalog, registry) and the `onepack` CLI;
- `pocock` and `pstack` as skills-directory plugins, **off** until a repo turns them on;
- the `specify` and `openspec` CLIs.

Per repo, nothing changes: `onepack add pocock` writes both `pocock@onepack` (Mac) and `pocock@skills-dir` (cloud) to `.claude/settings.json`; commit it once and the pack is on in both places. A pack turned on from inside a cloud session loads in the next cloud session. `rea` is Mac only.

Updates reach cloud when the environment cache is rebuilt (about every 7 days, or when the setup script or network settings change).

## Layout

- `packs.json` — registry (groups, packs, upstream sources).
- `bin/onepack` — the CLI.
- `skills/onepack/` — the `/onepack` skill (follows the Skill Standard).
- `cloud/` — setup script and skill list for Claude Code cloud environments.
- `guides/` — hand-written pack guides; `CATALOG.md` — generated from guides + plugin skill lists.
- `plugins/` — built plugin packs (generated; never edit); `overlays/` — your changes to packs.
- `scripts/build.py`, `.github/workflows/build.yml` — daily rebuild; `.claude-plugin/marketplace.json` — generated.
